# Special Animal Care PWA Requirements

이 문서는 사용자가 제시한 전체 기능 개요를 이 프로젝트의 기준 요구사항으로 정리한 것이다. 이후 구현, 리팩터링, UI 수정 시 이 문서를 우선 참고한다.

## 1. 메인 지도 & 리뷰

상위 UX는 네이버 지도를 많이 참고한다.

### 발견 중심 범위

- 현재 지도 기능은 `발견` 흐름에 집중한다.
- 핵심 흐름은 병원 검색, 지도 마커 탐색, 병원 목록, 병원 상세, 리뷰 확인과 작성이다.
- 대중교통, 내비게이션, 예약 기능은 지도 화면에 구현하지 않는다.
- 별도의 저장 메뉴는 지도 화면에 두지 않는다.
- 좋아요한 병원과 리뷰는 프로필의 나의 활동에서 관리한다.
- 네이버 지도의 정보 위계, 목록/상세 전환, 모바일 바텀시트 동작을 참고하되 프로젝트 색상 토큰을 유지한다.

### 지도 기본 구조

- 화면 지도는 Google Maps JavaScript API로 표시한다.
- 지도용 브라우저 키는 빌드·배포 환경의 `VITE_GOOGLE_MAPS_API_KEY`로 주입하고, 코드나 Git 기록에 하드코딩하지 않는다.
- 브라우저 Geolocation API로 사용자의 현재 위치를 가져온다.
- 병원 검색·상세 데이터는 지도 SDK와 분리하며, 저장된 병원 좌표만 Google 지도 마커에 사용한다.
- 자신의 위치를 기준으로 한 지도가 나타난다.
- 화면은 지도가 중심이고, 검색과 필터는 지도 위 오버레이로 배치한다.
- 검색창은 분류 태그 상단에 위치한다.
- 검색창 구성:
  - 병원 이름 검색
  - 내 위치 버튼
- 내 위치 버튼을 누르면 지도 중심이 내 위치로 이동한다.
- 모바일 병원 목록은 별도 `목록 보기` 버튼 없이 지도 하단에 일부가 항상 보이는 바텀시트로 노출한다. 목록과 상세는 사용자가 손잡이를 위아래로 끌어 높이를 연속 조절하며, 손을 놓은 높이를 그대로 유지하되 시트 상단이 검색·필터 영역을 덮지 않는다. 지도·병원·필터 선택은 사용자가 정한 바텀시트 높이를 임의로 변경하지 않는다.
- 모바일 지도 위 필터는 `영업 중`만 표시한다. `거리순`, `평점순` 정렬은 바텀시트 안에 거리순부터 배치하며 기본값도 거리순으로 한다.
- 병원 목록의 `증상·질병별 병원`에서 거식·먹이 거부, 탈피, 배변, 산란과 리뷰 작성 폼의 진단명별로 관련 리뷰 및 공개 검색 근거가 있는 병원을 최대 5곳까지 표시한다.
- 증상·질병별 화면에는 보호자가 즉시 확인할 환경·기록 항목, 피해야 할 임의 처치, 신속한 진료가 필요한 징후와 의료 안내 면책을 함께 표시한다.
- Q&A 질문 제목·본문·첨부 기록에서 지원하는 증상·질병 키워드가 확인되면 해당 병원 TOP 5 화면으로 이동하는 행동을 제공한다.
- 화면 상단 분류 태그:
  - 전체
  - 파충류
- 병원 지도와 병원 리뷰 탐색은 파충류 진료 병원을 우선 대상으로 한다.
- 조류, 설치류, 양서류, 기타만 근거가 있는 병원은 지도 API 결과, 정적 병원 데이터, 지도 마커, 병원 목록에서 제외한다.

### 병원 마커

- 병원은 H 마커로 표시한다.
- 모든 병원 마커에 해당 병원의 앱 내부 리뷰 개수를 배지로 표시한다.
- 리뷰 개수는 임의 값이나 외부 리뷰 수가 아니라 앱에 저장된 실제 병원 리뷰 데이터를 사용한다.
- 기본 마커:
  - 배경은 민트색
  - H 마커는 흰색
- 좋아요한 병원은 마커 옆에 하트가 표시된다.
- 해당 분류 리뷰가 5개 이상이면 신뢰도 확인을 위해 마커 색이 파란색으로 전환된다.

### 병원 클릭 시 정보

병원 마커를 클릭하면 병원 정보가 열린다.

표시 정보:
- 병원 이름
- 내 위치로부터 떨어진 거리
- 최근 진료한 종
  - 리뷰 데이터에서 가져온다.
- 리뷰 개수
- 하트 좋아요 버튼
- 분류 태그
- 리뷰 영역

병원 상세 패널은 다음 순서로 구성한다.

- 상단: 병원명, 좋아요, 닫기
- 기본 정보: 주소와 작은 복사 버튼, 내 위치에서의 거리, 현재 영업 상태, 오늘 운영시간, 요일별 운영시간
  - 오늘 운영시간은 단일 카드 안에서 왼쪽 제목·상태와 오른쪽 `요일 시간`을 2열로 정렬한다.
  - 중간 휴게시간이 있으면 오늘 시간 바로 아래에 작은 보조 텍스트로 표시한다.
  - 요일별 운영시간은 16px 이상 간격을 둔 아코디언으로 부드럽게 펼치고 접는다.
- 주요 액션: 전화하기, 길찾기
- 연락처: 전화번호
- ExoCare 리뷰: 리뷰 작성과 앱 사용자 리뷰 목록 또는 빈 상태
- 별점: Google 별점과 ExoCare 방문 리뷰 평균을 산술 평균한 통합 별점
  - ExoCare 방문 리뷰가 없으면 Google 별점을 그대로 사용한다.
  - Google 별점이 없으면 ExoCare 방문 리뷰 평균을 사용한다.
  - Google 평가 수와 Google 리뷰 본문은 표시하지 않는다.

최근 진료 리뷰 안내, 상단 리뷰 수, 출처 문구, Google 리뷰 본문 미제공 안내와 중복 평점은 상세 패널에 표시하지 않는다.

### 리뷰 화면

- 리뷰 보기는 외부 사이트로 이동하지 않고 앱 내부에서 열린다.
- 네이버 지도 리뷰 UI를 참고한다.
- 리뷰가 없으면 리뷰가 없다고 표시한다.
- 리뷰가 있으면 스크롤 가능한 목록으로 보여준다.
- 사진/영상 리뷰를 지원한다.
- 사진 보기와 글 보기 전환이 가능해야 한다.
- 리뷰는 요약되어 나열된다.
- 요약 기준:
  - 분류
  - 동물 병원
  - 종
- 상세보기에서는 요약 없이 전체 리뷰를 펼쳐서 볼 수 있다.
- 내가 쓴 리뷰에는 수정/삭제 버튼이 있다.
- 리뷰 좋아요 버튼이 있다.

### 리뷰 작성

- `+` 버튼으로 리뷰 작성이 가능하다.
- 리뷰 작성 폼에서는 별점을 입력받지 않는다.
- 모바일에서는 단계별 `이전`·`다음` 행동 영역을 화면 하단에 항상 노출하고, 마지막 단계의 기본 제출 문구는 `리뷰 작성 완료`로 표시한다.
- 영수증/결제 내역 인식을 지원한다.
- 리뷰 폼 필드:
  - 반려동물 선택
    - 마이 펫에 등록된 반려동물 정보가 선택지로 표시된다.
  - 진료 내용 직접 입력, 선택
  - 병명, 선택
  - 방문한 동물 병원 선택
    - 병원 리스트에서 선택 가능
  - 수의사 의견
  - 비용 입력
    - 숫자만 입력
    - 쉼표 자동 입력
    - 선택
  - 날짜 선택
    - 달력 표시
  - 처방받은 약 입력, 선택
  - 직접 작성 글
  - 사진 첨부
    - 최대 3장
- 리뷰 작성 시 해당 날짜에 동물 기록이 추가된다.
- 임시 저장 기능이 필요하다.
- 현재 병원과 선택한 마이 펫에 해당하는 기존 진료 기록을 불러올 수 있다.
- 진료 기록을 선택하면 방문 날짜, 병원, 진료비, 병명/진단명, 처방과 리뷰 본문 초안이 자동 입력되며 이후 직접 수정할 수 있다.
- 병명/진단명과 처방은 양서류·파충류 진료 추천 항목을 검색해 선택하거나 목록에 없는 값을 직접 입력할 수 있다.
- 다음 예정일과 알림은 리뷰 작성이 아니라 다이어리의 진료 기록 작성에서 입력하고 기존 병원 루틴 및 캘린더 저장 구조에 연결한다.
- 약 종류 전용 필드는 사용하지 않고 기존 리뷰 데이터의 `diagnosis`, `treatment` 필드를 병명/진단명과 처방으로 사용한다.

### 리뷰 태그

- 태그는 `양서·파충류 전문성`과 `일반 병원 경험`으로 나누며 전문성 태그를 먼저 표시한다.
- 전문성 태그에는 종 이해, 사육환경, 온습도·UVB·영양, 탈피·산란·MBD, 기생충·분변·엑스레이 검사, 응급 대응과 투약 안내 경험을 포함한다.

기본 리뷰 태그:
- 수의사 님이 친절해요
- 병원의 위생이 좋아요
- 설명이 자세해요
- 가격이 합리적이에요
- 아이를 조심스럽게 잘 다뤄주세요
- 진료 장비가 잘 갖춰져 있어요
- 예약 시간이 잘 지켜져요
- 대기 시간이 짧아요
- 응급 상황에 빠르게 대응해요
- 검사 결과를 쉽게 알려줘요
- 집에서 관리하는 법을 알려줘요
- 동물 특성을 잘 이해해요
- 과잉진료가 없어요
- 비용 안내가 투명해요
- 병원 분위기가 차분해요
- 재방문하고 싶어요
- 태그 직접 작성 가능

## 2. 마이 펫

- 등록된 펫이 없으면 분류 필터와 `+` 버튼 대신 `나의 첫 반려동물 등록하기` 버튼을 표시한다.
- 첫 펫 등록 후에는 분류 필터와 `+` 버튼을 표시한다.
- 마이 펫 카드는 펫의 사진, 이름, 성별, 종을 기본 정보로 표시한다.
- 웹 화면에서는 다이어리에 오늘 예정된 루틴이 있을 때 카드 오른쪽에 `오늘 할 일`을 표시한다.
- 오늘 할 일에는 완료 개수와 루틴 이름을 간결하게 표시하며, 완료한 루틴은 완료 상태로 구분한다.
- 활성 루틴은 있지만 오늘 예정된 항목이 없으면 카드 오른쪽에 `오늘 예정 없음`을 표시한다.
- 모바일 마이 펫 홈은 원형 펫 선택 목록, 선택 펫 요약, 오늘의 케어 최대 3개, 이번 주 실제 루틴 달성률과 다이어리 연결 CTA 순서로 표시한다.
- 펫 요약 카드를 누르면 펫 상세로 이동하며, 오늘의 케어 전체보기와 하단 CTA는 해당 펫이 선택된 다이어리로 이동한다.
- 펫 상세는 실제 저장 데이터에 한해 기본 정보, 기록 요약, 기록 사진을 표시하고 기록하기·정보 수정·삭제를 기존 동작에 연결한다.
- 펫 사진은 Base64 문자열이 아니라 Supabase Storage의 사용자별 경로에 저장하고, 펫 데이터에는 공개 파일 URL만 저장한다.
- 펫 등록은 기본 정보와 추가 정보의 두 화면으로 구성한다. 기본 정보는 사진(선택), 이름, 종, 성별, 현재 몸무게를 입력하고 추가 정보는 생년월일, 입양일, 특징, 메모를 입력한다.
- 성별은 수컷·암컷·미구분을 균등한 3열로 표시한다.
- 펫 등록의 필수 항목은 이름, 동물 분류, 세부 종, 성별이며 사진과 몸무게, 날짜, 특징, 메모는 선택 항목이다.
- 나이는 숫자 입력과 `살` 단위를 한 그룹으로 표시하고, 몸무게는 입력창 오른쪽에 `g/kg` 단위 세그먼트를 붙인다.
- 선택한 펫 사진은 드래그로 위치를 조정할 수 있음을 방향 표식과 안내 문구로 표시한다.
- 모바일 마이 펫 목록은 상단 중앙 제목과 우측 원형 추가 버튼, 등록 펫의 세로 카드 목록으로 구성한다. 카드는 사진, 이름, 종, 생년월일과 계산 가능한 나이를 실제 데이터로 표시한다.
- 모바일 펫 상세는 큰 사진 헤더, 뒤로가기·더보기·수정 버튼, 이름·종·성별·생년월일 요약과 프로필·기록·루틴·통계 탭으로 구성한다.
- 마이 펫의 기능 마커는 둥근 민트 배경과 동일한 선 굵기의 단색 SVG 아이콘 체계를 사용하며 이모지를 기능 아이콘으로 사용하지 않는다.

## 3. 질문 QNA

- 질문 목록에서는 머리글만 나타난다.
- 클릭 후 자세한 질문이 나온다.
- 펼쳐서 더보기가 가능하다.
- 질문 작성 기능이 있다.
- 작성 폼:
  - 내 펫
  - 머리글
  - 작성 내용
  - 임시저장
- 작성 시 동물 기록에 추가된다.
- 질문 하단에는 댓글 기능이 존재한다.

## 4. 내 펫

- `+` 버튼으로 펫을 등록한다.
- 등록은 순서대로 화면 전환된다.
- 플로우:
  - 종류 선택 화면
  - 종 등록 화면
  - 세부 정보 입력
  - 최종 확인
  - 등록 완료
- 종류 선택:
  - 파충류
  - 조류
  - 설치류
  - 양서류
  - 기타
- 입력 필드:
  - 종, 직접 입력
  - 성별
    - 수컷
    - 암컷
    - 미구분
  - 이름, 닉네임
  - 사진

## 5. 캘린더

- 상단에서 펫 선택 가능.

### 배변 상태 NOTICE 흐름

- 배변 기록 저장 직후 별도 대응 패널을 열지 않고, 상태 안내는 다이어리 상단 `NOTICE`에서만 제공한다.
- 정상 배변은 추가 대응 없이 기록만 저장한다.
- 건조 또는 묽은 배변이 처음 기록되면 해당 날짜의 온도·습도 기록을 확인한다. 둘 중 하나라도 없으면 `온습도 기록하기`를 제공하고, 저장된 적정 범위를 벗어난 경우에만 범위를 확인하도록 안내한다.
- 건조 배변에는 기존 루틴 구조를 이용한 배변 확인용 임시 분무·물그릇 루틴을 추가할 수 있다. 다음 배변이 정상이면 임시 루틴 유지·종료를 묻는다.
- 바로 다음 배변에서도 같은 건조 또는 묽음 상태가 이어지면 같은 환경 조절을 반복 권고하지 않고 `기록 모아보기`, `Q&A 작성하기`, `병원 찾기`를 제공한다. 임의의 의료 횟수 기준은 사용하지 않는다.
- 혈변과 이물질은 일반 환경 조절 버튼을 섞지 않고 기존 진료 연결 흐름을 사용한다.

## Cross Feature Rules

- 좋아요 데이터는 프로필의 나의 활동과 연결한다.
- 병원 좋아요는 `hospital_likes`에 사용자별로 저장하고 로그인 시 서버 데이터를 기준으로 불러온다. localStorage는 사용자별 보조 캐시와 기존 데이터 최초 이전에만 사용한다.
- 임시 저장 데이터는 프로필에서 다시 이어 작성할 수 있어야 한다.
- 리뷰 작성과 질문 작성은 동물 기록/캘린더와 연결한다.
- 지도 병원 데이터와 리뷰 데이터는 서로 연결되어야 한다.

## 루틴 푸시 알림 운영 기준

- `care_plans`는 반복 규칙 원본이고 `daily_tasks`는 날짜별 occurrence다.
- 활성 루틴은 Asia/Seoul 날짜 기준 앞으로 14일의 occurrence와 최초 알림 작업을 미리 생성한다.
- 일정 생성은 루틴 생성·수정 직후와 매일 Cron에서 실행하며 완료 여부에 의존하지 않는다.
- 알림은 정시, 미완료 시 10분 뒤, 계속 미완료 시 다음 날 같은 시각 순서로 생성한다.
- 각 알림은 UNIQUE `dedupe_key`를 가지며 원자적 claim 후 한 번만 발송한다.
- 완료·건너뛰기는 해당 occurrence의 미발송 작업만 취소하고 다음 날짜 일정은 유지한다.
- 기기 알림 상태는 `Notification.permission`, 실제 `PushSubscription`, `push_subscriptions` 활성 행을 함께 동기화해 판단한다.
- 로그아웃 시 브라우저 구독은 재사용할 수 있게 유지하되 현재 계정의 endpoint 행은 비활성화한다.


## 병원 데이터 수집 정책

- PWA 프론트엔드는 네이버 지역 검색 API와 Google Places API를 직접 호출하지 않는다.
- 네이버 Search Client ID/Secret과 Google Places API 키는 서버 환경 또는 Supabase Secret에만 둔다.
- 병원 기본 데이터는 네이버 지역 검색 API와 Google Places API (New) 같은 서버 검색 공급자에서 주기적으로 수집한 뒤 `public/data/exotic-hospitals.json` 또는 DB에 저장한다.
- 수집은 전국 시/군/구와 단일 기본 검색어 `파충류 동물 병원`을 조합하고 낮은 동시성으로 순차 요청한다.
- 병원명과 주소를 정규화해 중복 병원을 하나로 병합한다.
- 지도용 `supportedAnimals`에는 `reptile`을 저장한다.
- 양서류, 조류, 설치류, 기타 또는 일반 특수동물 근거만 있는 병원은 지도 데이터에서 제외한다.
- `파충류 동물 병원` 검색, 사진 지도 기반 초기 데이터 또는 Google Places API (New)의 파충류 병원 검색으로 확인된 병원은 `confirmed`로 분류한다.
- Google Places API (New) 결과는 Supabase Edge Function에서만 병합하며 프론트엔드에는 Google API 키를 전달하지 않는다.
- 병원 기본 목록은 Supabase `hospitals` 테이블에서 읽고, 네이버 지역 검색 기반 서버 수집은 매월 1일 낮은 동시성으로 갱신한다. 지도 진입, 검색어 입력, 지도 이동으로 외부 검색 API를 반복 호출하지 않는다.
- Google Places에서 장기 저장하는 값은 정책상 허용되는 `placeId`로 제한한다. 전화번호, 평점, 사용자 평점 수, 리뷰 본문, 정규 영업시간과 현재 영업시간은 사용자가 병원을 선택했을 때 Edge Function에서 조회하고 화면 메모리에서만 유지한다.
- Google Text Search로 장소를 식별한 뒤 Place Details를 요청하며, Place Details가 리뷰 본문을 생략해도 평점과 리뷰 수는 별도로 표시한다.
- `currentOpeningHours`가 있으면 휴일 또는 임시 변경을 반영한 현재 영업시간으로 우선 사용하고, 없으면 `regularOpeningHours`를 사용한다. 요일별 설명은 Google 원문 배열을 보존한다.
- 과거 호환용 영업시간 컬럼은 유지하되 새 Google 상세 응답을 장기 저장하지 않는다. 시점에 따라 변하는 `is_open_now`는 병원 상세을 열 때 다시 확인한다.
- Google 리뷰 본문과 Google 평가 수는 병원 목록과 상세에 표시하지 않는다.
- 병원 목록과 상세의 별점은 Google 별점과 ExoCare 방문 리뷰 평균을 산술 평균해 표시한다. 앱 방문 리뷰가 없으면 Google 별점을 그대로 사용한다.
- 리뷰 많은 순은 ExoCare 방문 리뷰 수를, 평점 높은 순은 화면에 표시하는 통합 별점을 기준으로 정렬한다.
- `영업 중` 필터를 켤 때는 현재 검색 결과의 병원 상태를 먼저 갱신한다. `isOpenNow === true`인 병원과 영업 상태를 제공받지 못한 병원을 함께 표시하되, 상태 미제공 병원은 `영업정보 없음`으로 구분하고 `영업 중`으로 단정하지 않는다.
- 전화번호·평점 등 Places 상세정보는 30일 캐시를 유지하되 시간에 따라 변하는 영업 상태는 15분 캐시로 갱신한다.
- Supabase Realtime은 DB 변경 전파에 사용하며 외부 Places 데이터를 자동 갱신하는 스케줄러로 간주하지 않는다.
- 앱 리뷰, 좋아요, 최근 진료 종과 사용자 활동은 앱 DB/사용자 데이터로 즉시 갱신하며 주기 수집을 기다리지 않는다.

## 탈피 완료 확인 시점

- `탈피 시작` 기록 직후에는 탈피 상태 안내와 완료 확인 UI를 표시하지 않는다.
- 탈피 시작일로부터 2일이 지난 시점부터 `탈피 중` / `탈피 완료` 선택을 표시한다.
- 시작과 완료 기록이 축적되면 완료된 탈피 기간의 평균을 계산해 다음 완료 확인 안내에 표시한다.

## 알림 허용 유도

- 앱 진입 즉시 브라우저 알림 권한을 요청하지 않는다.
- 현재 펫에 활성 루틴이 있고 현재 기기가 구독되지 않은 경우에만 다이어리에 알림 안내를 표시한다.
- 사용자가 `알림 켜기`를 누른 명시적 사용자 동작 안에서만 `Notification.requestPermission()`을 실행한다.
- `나중에`를 선택하면 7일 동안 같은 기기·계정에서 안내를 다시 표시하지 않는다.
- 이미 구독됐거나 브라우저에서 차단된 경우, 지원되지 않는 환경에서는 유도 안내를 노출하지 않는다.
- VAPID 공개키가 변경되었을 때는 현재 브라우저 구독의 `applicationServerKey`와 비교한다. 일치하지 않으면 기존 구독과 DB 활성 상태를 해제하고 새 키로 기기 등록을 다시 요청한다.

## 수질 확인 기록

- 수질 확인 루틴을 완료하면 해당 날짜의 다이어리 상세에 `수질 확인` 아이콘과 이름을 표시한다.
- 체크 직후뿐 아니라 페이지 재접속 후에도 DB의 `record_type`, `memo`, `record_date`, `daily_task_id`를 기준으로 동일한 기록을 복원한다.
- 과거에 요약 payload로 저장된 수질 확인 기록도 DB의 정규 컬럼을 병합해 표시한다.

## 기록 모아보기 탈피 UI

- 기록 모아보기의 탭, 그래프 제목, 경고 분류명은 `탈피`로 통일한다.
- `탈피 중` 같은 진행 상태는 좁은 탭 안에 넣지 않고 탈피 본문 영역에만 짧게 표시한다.
- 모바일의 네 가지 기록 탭은 한 줄을 유지하며 글자가 두 줄로 갈라지지 않아야 한다.

## 루틴 완료 저장 원칙

- 일일 루틴 완료 상태와 해당 캘린더 기록은 함께 확정되어야 하며 한쪽만 저장된 상태를 새로 만들지 않는다.
- 서버 저장이 실패하면 화면에서 완료 체크나 캘린더 기록을 먼저 확정하지 않고 사용자의 입력을 유지한다.
- 과거 오류로 캘린더 기록만 존재하는 일일 루틴은 다시 완료할 때 중복 기록을 만들지 않고 기존 기록을 재사용해 완료 상태를 복구한다.


## 다이어리 NOTICE 경고 표시

- 다이어리 메인 화면의 분석 경고는 별도의 큰 카드로 중복 표시하지 않고 상단 `NOTICE` 영역에 모아 표시한다.
- 각 경고는 단계 배지와 핵심 문장만 우선 표시하고 Q&A, 병원 찾기, 해결 확인, 탈피 확인 동작을 같은 영역에서 제공한다.
- 경고가 없을 때는 마지막 먹이·배변·탈피 등 최근 기록 경과 안내를 표시한다.
- 모바일 다이어리에서는 전역 프로필 버튼이 캘린더 버튼을 가리지 않아야 하며, 캘린더를 열면 월간 달력과 선택 날짜 일정이 명확하게 표시되어야 한다.
- 이상 배변 다음에 정상 배변이 기록된 경우, 활성 배변 확인용 임시 루틴이 없으면 정상화 NOTICE를 다시 표시하지 않는다. 임시 루틴이 남아 있을 때만 유지·종료 선택을 표시한다.

## 모바일 다이어리 메인 구성

- 모바일 다이어리의 첫 화면은 펫 선택, 선택 날짜와 주간 이동, 오늘 할 일, 상황별 기록 추가 순서로 구성한다.
- 날짜 영역에서 월간 캘린더 열기, 오늘 복귀, 이전·다음 주 이동을 제공한다.
- 오늘 할 일은 루틴명, 예정 시간, 완료 체크를 한눈에 확인할 수 있게 표시하고 기존 루틴 추가 흐름으로 연결한다.
- 기록 추가 화면은 정기 관리와 상황별 기록을 나눠 보여주며 약 기록을 포함한다.
- 모바일 다이어리 메인에는 최근 기록 목록을 표시하지 않아 첫 화면의 세로 스크롤을 줄인다.

## 다이어리 화면 흐름과 아이콘

- 모바일 다이어리는 홈, 오늘의 루틴 전체보기, 루틴 완료 피드백, 상황별 기록 선택, 세부 기록 작성, 기록 모아보기 순서로 연결한다.
- 상황별 기록 선택 화면에서는 배변, 탈피, 병원 방문, 약, 메이팅, 산란, 기타를 제공한다.

## 모바일 다이어리 리디자인

- 사용 흐름은 월간 달력 확인, 선택 날짜의 루틴·기록 확인, 기록 종류 선택과 작성, 과거 기록 분석 순서를 따른다.
- 월간 달력은 날짜별 기록을 작은 상태 점으로 표시하고 오늘은 Primary 원, 선택한 다른 날짜는 연한 Primary 배경으로 구분한다.
- 날짜를 선택하면 해당 날짜의 하루 기록 상세를 바로 열고 전체·루틴·상황 기록 필터와 `기록 추가하기`를 제공한다.
- 오늘의 루틴은 완료 수와 진행 막대를 표시하며 각 항목에서 바로 완료할 수 있다.
- 기록 종류 선택은 정기 관리(먹이, 분무, 물그릇, 온습도, 청소)와 상황 기록(배변, 탈피, 병원 방문, 약, 메이팅, 산란, 기타)으로 나눈다.
- 기록 작성은 날짜, 시간, 유형별 입력, 메모, 사진을 한 화면에서 제공하고 기존 저장 구조를 재사용한다.
- 하루 상세는 기록을 시간 순서로 표시하며 시간, 상태·메모와 사진 썸네일을 제공한다.
- 기록 모아보기는 주간·월간·전체 기간 필터, 주요 기록 횟수, 실제 데이터가 존재하는 체중 및 온습도 그래프를 제공한다.
- 기록 상세에서는 사진과 입력 내용을 확인하고 수정 또는 삭제할 수 있다.
- 모바일 하단 내비게이션은 내 펫, 다이어리, 지도, Q&A 네 항목만 사용한다.
- 세부 기록 작성은 모바일에서 독립된 전체 화면처럼 표시하되 기존 기록 저장 구조를 재사용한다.
- 다이어리의 루틴, 상황 기록, 완료 상태, 캘린더 기록 마크는 동일한 플랫 선형 SVG 아이콘 체계를 사용한다.
- 아이콘 색상은 `src/index.css`의 Primary 및 상태 토큰을 사용하며 구형 입체 PNG 마크와 혼용하지 않는다.

## 다이어리 날짜 및 NOTICE 동작

- 모바일 다이어리 첫 화면에는 월간 캘린더를 상시 노출하지 않고 상단 캘린더 버튼을 눌렀을 때 별도 캘린더 화면으로 이동한다.
- 미래 날짜에는 루틴을 완료 기록처럼 표시하지 않으며 기록 작성 동작을 제공하지 않는다.
- 과거 날짜의 하루 상세는 기존 기록 열람만 허용하고 기록 추가, 메모 추가, 수정, 삭제를 제공하지 않는다.
- 오늘 완료한 루틴의 연결 기록을 삭제하면 일일 작업도 미완료로 되돌려 완료 표시가 다시 생기지 않게 한다.
- 배변 NOTICE는 첫 건조·묽음 단계에서 온습도 또는 최근 기록 확인을 먼저 제공한다. 반복 상태에서만 기록 모아보기, Q&A 작성, 병원 찾기를 함께 제공한다.
- 이물질은 Q&A 작성 후 병원 찾기 순서, 혈변은 병원 찾기 후 Q&A 작성 순서로 제공한다.

## 모바일 다이어리 최종 화면 흐름

- 최신 디자인 시안을 우선하여 다이어리 메인에서 월간 캘린더와 오늘의 루틴을 함께 표시한다.
- 캘린더 날짜 선택 시 해당 날짜의 기록 화면으로 이동하며 루틴과 상황 기록을 두 탭으로 구분한다.
- 오늘의 루틴 항목을 누르면 루틴 확인 화면을 열고 완료하기를 누르면 완료 피드백 화면을 표시한다.
- 마지막 미완료 루틴까지 완료하면 `오늘의 루틴을 모두 완료했어요!` 전체 완료 화면을 표시한다.
- 기록 추가 목록은 탈피 기록, 배변 기록, 메이팅 기록, 산란 기록, 진료 기록 순서의 세로 목록으로 표시한다.
- 선택 날짜에 기록이 없으면 `아직 기록이 없어요.` 빈 상태와 기록 추가 버튼을 표시한다.

## 2026-09-10 최신 전체 화면 시안 우선 규칙

- 2026-09-10 첨부 전체 플로우 이미지가 이전 디자인 문구보다 우선한다. 새 디자인을 임의로 생성하지 않는다.
- React와 Tailwind를 사용하고, 공통 Button / Field / ChoiceGroup / FormActions / FlowHeader / ProgressBar를 재사용한다.
- 하단 메뉴는 흰색 바탕에 내 펫·다이어리·병원 찾기·Q&A 네 항목이며 선택한 아이콘은 민트색으로 강조한다.
- 내 펫 메인은 세로 펫 카드, 사진·이름·종·성별, 오늘 루틴 진행률과 남은 루틴을 표시한다.
- 펫 추가는 시작 → 기본 정보 → 선택 루틴 → 등록 완료 → 내 펫 보기 순서로 연결한다.
- 다이어리 메인은 날짜와 오늘의 루틴을 표시하고 날짜를 누르면 별도 월간 캘린더를 연다. 추가 버튼은 탈피·배변·메이팅·산란·진료 다섯 항목으로 연결한다.
- 기존 API, Supabase 인증·저장, 좋아요, 루틴 완료, 기록 연동과 푸시 동작은 보존한다.
- 첨부 캐릭터·케어 아이콘은 public/ui-flow-reference.png 원본의 해당 영역을 공통 컴포넌트로 표시한다. 별도 생성 이미지로 교체하지 않는다.

## 2026-09-12 다이어리 상단 액션과 캘린더

- 다이어리 상단의 원형 `+` 버튼은 기록 추가가 아니라 루틴 추가·관리 화면으로 연결한다.
- 원형 `+` 버튼은 루틴 관리 목록을 거치지 않고 새 루틴 작성 폼을 즉시 연다. 톱니바퀴만 기존 루틴 관리 목록을 연다.
- 상단에 별도의 캘린더 아이콘 버튼을 두고 월간 캘린더는 해당 버튼 또는 날짜 버튼을 눌러 연다.
- 상황 기록 추가는 삭제하지 않고 오늘의 루틴 아래 `기록하기` 버튼으로 분리한다.
- 캘린더에서 탈피 예상 기간은 민트 계열, 산란 예상 기간은 Accent 계열로 서로 다르게 칠하고 같은 색의 범례를 제공한다.
- 탈피 예상 기간은 계산된 탈피 예상일을 기준으로 2일 전부터 2일 후까지 총 5일로 표시하며 파란색 위치 토큰으로 칠한다.
- 예상 기간은 날짜별 캡슐을 반복하지 않고 시작과 끝만 둥근 하나의 연속된 띠로 표시하며, 주 경계에서는 띠를 자연스럽게 나눈다.

## 2026-09-12 기록 모아보기 그래프

- 기록 모아보기는 분석 문장과 횟수 요약을 본문 상단에 반복 노출하지 않고 기간·기록 종류 선택과 그래프를 중심으로 구성한다.
- 체중, 온도, 습도, 탈피·배변·산란 주기 그래프는 모바일 가로 폭을 채우며 선, 점, 기준선을 명확히 구분한다.
- 날짜와 측정값은 그래프 판독에 필요한 축 보조 정보로만 간결하게 표시한다.
