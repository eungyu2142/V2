# 중학생을 위한 HTTP와 URL 공부 문서

이 문서는 디미고 면접을 준비하는 중학교 3학년이 HTTP와 URL을 이해하고, 자신이 만든 **파작파작** 웹앱과 연결해서 설명할 수 있도록 작성했다.

처음부터 모든 용어를 외우려고 하지 말자. 다음 한 문장을 먼저 이해하면 된다.

> URL은 찾아갈 주소이고, HTTP는 그 주소에 요청을 보내고 응답을 받는 약속이다.

---

## 1. 웹앱을 사용할 때 실제로 일어나는 일

사용자가 브라우저에서 파작파작에 접속한다고 생각해 보자.

```text
사용자
  ↓ 주소 입력 또는 버튼 터치
브라우저와 React 앱
  ↓ HTTP 요청
서버 또는 Supabase
  ↓ 데이터베이스 조회
HTTP 응답
  ↓
React가 화면을 다시 그림
```

예를 들어 사용자가 병원을 검색하면 다음 과정이 일어난다.

1. 사용자가 검색어를 입력한다.
2. React가 검색어를 읽는다.
3. 앱이 Supabase Edge Function에 HTTP 요청을 보낸다.
4. Edge Function이 병원 검색 API를 호출한다.
5. 검색 결과가 JSON 형식으로 돌아온다.
6. React가 받은 병원 목록을 화면에 표시한다.

React는 화면을 담당하고, HTTP는 React와 서버가 대화할 수 있게 해 준다.

## 2. URL이란 무엇인가?

URL은 **Uniform Resource Locator**의 약자다. 인터넷에 있는 자원의 위치를 나타내는 주소다.

집을 찾아갈 때 도로명 주소가 필요하듯이, 브라우저가 웹페이지나 데이터를 찾으려면 URL이 필요하다.

파작파작의 개발 주소를 예로 들어 보자.

```text
http://localhost:5173/profile?tab=posts#top
```

이 주소는 여러 부분으로 나뉜다.

```text
http:// | localhost | :5173 | /profile | ?tab=posts | #top
프로토콜     호스트       포트       경로        쿼리         프래그먼트
```

### 2-1. 프로토콜 또는 스킴

```text
http://
```

어떤 규칙으로 통신할지를 나타낸다.

- `http`: 암호화되지 않은 HTTP 통신
- `https`: 암호화된 HTTP 통신

주소를 배달 방법에 비유하면 URL이 목적지이고, 프로토콜은 목적지까지 물건을 전달하는 규칙이다.

### 2-2. 호스트

```text
localhost
```

접속할 컴퓨터나 서버를 나타낸다.

- `localhost`: 현재 사용 중인 자기 컴퓨터
- `127.0.0.1`: 자기 컴퓨터를 가리키는 특별한 IP 주소
- `pajakpajak.vercel.app`: 배포된 서버를 가리키는 도메인 예시

`localhost`는 다른 사람의 컴퓨터를 뜻하지 않는다. 휴대전화에서 `localhost`를 입력하면 개발용 PC가 아니라 **휴대전화 자기 자신**을 찾는다.

같은 와이파이의 휴대전화에서 PC의 개발 서버에 접속할 때는 다음처럼 PC의 사설 IP 주소를 사용한다.

```text
http://192.168.0.10:5173
```

실제 IP 주소는 네트워크 환경에 따라 달라진다.

### 2-3. 포트

```text
:5173
```

한 컴퓨터 안에서 어떤 프로그램과 통신할지를 구분하는 번호다.

아파트 주소가 컴퓨터의 IP라면 포트는 그 아파트의 호수와 비슷하다.

- Vite 개발 서버는 보통 `5173`을 사용한다.
- HTTP 기본 포트는 `80`이다.
- HTTPS 기본 포트는 `443`이다.

기본 포트는 주소에서 생략할 수 있다.

```text
https://example.com:443
https://example.com
```

위 두 주소는 일반적으로 같은 곳을 의미한다.

포트가 이미 다른 프로그램에서 사용 중이면 Vite가 `5174`, `5175`처럼 다음 번호를 선택할 수 있다. 따라서 터미널에 표시된 실제 포트를 확인해야 한다.

### 2-4. 경로

```text
/profile
```

서버나 웹앱 안에서 원하는 자원의 위치를 나타낸다.

예시:

```text
/profile
/pets
/hospitals/123
```

`/hospitals/123`은 보통 ID가 `123`인 병원 자원을 뜻하도록 설계한다.

### 2-5. 쿼리 문자열

```text
?tab=posts&sort=latest
```

경로에 추가 조건을 전달한다. `?` 뒤에서 시작하며 `이름=값` 형태로 작성한다. 조건이 여러 개면 `&`로 연결한다.

```text
tab=posts
sort=latest
```

파작파작에서는 다음 주소처럼 현재 탭을 URL에 저장한다.

```text
http://localhost:5173/?tab=diary
```

코드에서는 `URLSearchParams`로 값을 읽는다.

```ts
const params = new URLSearchParams(window.location.search)
const tab = params.get('tab')
```

이때 `tab`에는 `diary`가 들어간다.

주의할 점은 쿼리 문자열에 비밀번호나 비밀 API 키를 넣으면 안 된다는 것이다. URL은 방문 기록, 서버 로그, 공유 화면 등에 노출될 수 있다.

### 2-6. 프래그먼트

```text
#top
```

페이지 안의 특정 위치나 화면 상태를 나타낸다. 일반적으로 `#` 뒤의 값은 HTTP 요청으로 서버에 전달되지 않고 브라우저에서 처리된다.

## 3. IP 주소와 도메인은 어떻게 다른가?

### IP 주소

네트워크에서 컴퓨터를 식별하는 숫자 주소다.

```text
192.168.0.10
```

### 도메인

사람이 기억하기 쉽게 만든 이름이다.

```text
example.com
```

### DNS

DNS는 도메인 이름을 IP 주소로 바꿔 주는 시스템이다. 전화번호부와 비슷하다.

```text
사용자가 example.com 입력
→ DNS가 서버 IP 주소를 찾음
→ 브라우저가 해당 IP의 서버에 접속
```

면접에서는 다음처럼 설명할 수 있다.

> IP 주소는 네트워크에서 컴퓨터를 찾기 위한 숫자 주소이고, 도메인은 사람이 기억하기 쉽게 붙인 이름입니다. DNS가 도메인을 IP 주소로 변환합니다.

## 4. HTTP란 무엇인가?

HTTP는 **HyperText Transfer Protocol**의 약자다. 브라우저와 서버가 요청과 응답을 주고받는 규칙이다.

프로토콜은 서로 지켜야 하는 약속이다. 한쪽은 한국어로 말하고 다른 쪽은 전혀 다른 규칙으로 해석하면 대화할 수 없다. HTTP는 다음 내용을 일정한 형식으로 전달하도록 정한다.

- 어떤 자원을 원하는가?
- 어떤 행동을 원하는가?
- 추가 정보는 무엇인가?
- 요청이 성공했는가?
- 결과 데이터는 무엇인가?

---

## 5. HTTP 요청과 응답

HTTP 통신은 보통 요청과 응답 한 쌍으로 이루어진다.

```text
클라이언트 ── 요청(Request) ──→ 서버
클라이언트 ←─ 응답(Response) ── 서버
```

여기서 클라이언트는 서비스를 요청하는 프로그램이다. 웹에서는 주로 브라우저나 React 앱이 클라이언트다.

### 5-1. 요청의 구성

HTTP 요청에는 주로 다음 내용이 들어간다.

1. 메서드
2. URL
3. 헤더
4. 본문

예시:

```http
POST /qna HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer 사용자토큰

{
  "title": "도마뱀이 먹이를 먹지 않아요",
  "content": "어제부터 먹이를 거부합니다."
}
```

### 5-2. 응답의 구성

HTTP 응답에는 주로 다음 내용이 들어간다.

1. 상태 코드
2. 헤더
3. 본문

예시:

```http
HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": "qna-101",
  "title": "도마뱀이 먹이를 먹지 않아요"
}
```

## 6. HTTP 메서드

메서드는 서버에 어떤 행동을 원하는지 표현한다.

| 메서드 | 뜻 | 파작파작 예시 |
|---|---|---|
| `GET` | 조회 | 병원 목록 가져오기 |
| `POST` | 생성 | Q&A 글 등록하기 |
| `PUT` | 전체 교체 | 글의 전체 내용을 새 값으로 교체하기 |
| `PATCH` | 일부 수정 | 닉네임만 수정하기 |
| `DELETE` | 삭제 | 내가 작성한 질문 삭제하기 |

### GET

```http
GET /hospitals?category=reptile
```

파충류 관련 병원 데이터를 조회한다.

### POST

```http
POST /qna
```

새 질문을 만든다. 작성 내용은 보통 요청 본문에 넣는다.

### PATCH

```http
PATCH /pets/pet-1
```

`pet-1`의 일부 정보를 수정한다.

### DELETE

```http
DELETE /qna/qna-101
```

`qna-101` 질문을 삭제한다. 서버에서는 요청한 사용자가 작성자인지 확인해야 한다.

메서드는 의미를 전달하지만 보안을 자동으로 보장하지 않는다. DELETE 요청이라고 해서 무조건 삭제하면 안 된다. 서버가 로그인 상태와 권한을 검사해야 한다.

## 7. HTTP 상태 코드

상태 코드는 요청 결과를 세 자리 숫자로 알려 준다.

### 2xx: 성공

- `200 OK`: 요청 성공
- `201 Created`: 새로운 데이터 생성 성공
- `204 No Content`: 성공했지만 돌려줄 본문이 없음

### 3xx: 이동 또는 캐시

- `301 Moved Permanently`: 주소가 영구적으로 이동함
- `302 Found`: 임시로 다른 주소로 이동함
- `304 Not Modified`: 기존 캐시를 사용해도 됨

### 4xx: 요청 쪽 문제

- `400 Bad Request`: 요청 형식이나 값이 잘못됨
- `401 Unauthorized`: 로그인이 필요하거나 인증 정보가 잘못됨
- `403 Forbidden`: 로그인은 했지만 권한이 없음
- `404 Not Found`: 자원을 찾을 수 없음
- `409 Conflict`: 중복 아이디처럼 현재 데이터와 충돌함
- `429 Too Many Requests`: 너무 많은 요청을 보냄

`401`과 `403`의 차이는 자주 질문된다.

> 401은 주로 “누구인지 확인되지 않았다”는 뜻이고, 403은 “누구인지는 알지만 이 작업을 할 권한이 없다”는 뜻이다.

### 5xx: 서버 문제

- `500 Internal Server Error`: 서버 내부 오류
- `502 Bad Gateway`: 중간 서버가 잘못된 응답을 받음
- `503 Service Unavailable`: 서버가 잠시 요청을 처리할 수 없음

오류가 발생했다고 모두 `500`을 표시하면 안 된다. 입력값이 잘못되었다면 `400`, 로그인이 필요하다면 `401`처럼 원인에 맞는 코드를 사용해야 한다.

## 8. 헤더와 본문

### 헤더

요청이나 응답에 대한 부가 정보를 담는다.

자주 보는 헤더:

```text
Content-Type: application/json
Authorization: Bearer 토큰
Accept: application/json
```

- `Content-Type`: 보내는 데이터의 형식
- `Authorization`: 로그인 또는 권한을 증명하는 정보
- `Accept`: 받고 싶은 응답 형식

### 본문

실제로 전달할 데이터를 담는다.

```json
{
  "name": "파작이",
  "category": "reptile"
}
```

GET 요청은 보통 본문 대신 URL의 경로나 쿼리 문자열로 조회 조건을 전달한다. POST나 PATCH는 본문에 생성·수정할 데이터를 넣는 경우가 많다.

## 9. JSON이란 무엇인가?

JSON은 클라이언트와 서버가 데이터를 주고받을 때 자주 사용하는 텍스트 형식이다.

```json
{
  "id": "pet-1",
  "name": "파작이",
  "age": 2,
  "active": true
}
```

JSON은 다음 자료를 표현할 수 있다.

- 문자열: `"파작이"`
- 숫자: `2`
- 참·거짓: `true`
- 배열: `["먹이", "청소"]`
- 객체: `{ "name": "파작이" }`
- 빈 값: `null`

JSON에는 함수나 주석을 직접 넣을 수 없다.

## 10. HTTP와 HTTPS의 차이

HTTPS는 HTTP 통신을 TLS로 암호화한 방식이다.

HTTP 통신을 엽서에 비유하면 중간에서 내용을 볼 가능성이 있다. HTTPS는 내용을 암호화한 봉투에 넣어 전달하는 것과 비슷하다.

HTTPS가 제공하는 핵심은 다음과 같다.

1. 암호화: 중간에서 내용을 쉽게 읽지 못하게 한다.
2. 무결성: 전송 중 내용이 바뀌지 않았는지 확인한다.
3. 서버 인증: 접속한 서버가 올바른 서버인지 인증서로 확인한다.

로그인 비밀번호, 토큰, 개인정보를 다루는 실제 서비스는 HTTPS를 사용해야 한다.

HTTPS라고 해서 사이트의 모든 코드와 운영자가 무조건 안전하다는 뜻은 아니다. 통신 구간을 보호하는 기술이다.

## 11. 주소가 바뀌는 것과 서버 요청은 같은가?

항상 같지는 않다. 이 부분은 React 앱을 설명할 때 중요하다.

### 일반적인 웹페이지 이동

브라우저가 새 URL을 서버에 요청하고 HTML을 다시 받는다. 페이지 전체가 새로 로딩될 수 있다.

### SPA의 화면 전환

React로 만든 SPA는 JavaScript가 URL과 화면 상태를 바꾸면서 페이지 전체를 다시 받지 않을 수 있다.

파작파작에서는 다음 코드로 주소를 바꾼다.

```ts
window.history.replaceState(window.history.state, '', '/profile?tab=posts')
```

이 코드는 브라우저 주소를 바꾸지만 그 순간 서버에 새 HTML을 요청하지 않는다. React가 URL 상태를 읽고 프로필 화면을 표시한다.

정리하면 다음과 같다.

- URL 변경: 현재 위치나 화면 상태를 표현할 수 있음
- HTTP 요청: 서버에서 데이터나 파일을 가져오거나 변경함
- SPA에서는 URL이 바뀌어도 전체 페이지 요청이 발생하지 않을 수 있음

## 12. `fetch`는 무엇을 하는가?

브라우저의 `fetch` 함수는 JavaScript에서 HTTP 요청을 보낼 때 사용한다.

```ts
const response = await fetch('/data/exotic-hospitals.json')
const hospitals = await response.json()
```

과정은 다음과 같다.

1. JSON 파일에 GET 요청을 보낸다.
2. 응답이 올 때까지 기다린다.
3. 응답 본문을 JSON으로 해석한다.
4. 병원 데이터를 변수에 저장한다.

`fetch`는 404나 500 응답을 받았다고 항상 자동으로 예외를 발생시키지는 않는다. 따라서 상태를 직접 확인하는 습관이 좋다.

```ts
const response = await fetch('/api/hospitals')

if (!response.ok) {
  throw new Error(`요청 실패: ${response.status}`)
}

const data = await response.json()
```

## 13. 파작파작과 Supabase Edge Function

파작파작은 병원 상세 정보를 가져올 때 Supabase Edge Function을 호출한다.

간단히 표현하면 다음 구조다.

```text
파작파작 React 앱
→ Supabase Edge Function
→ 외부 병원 검색 API
→ Edge Function
→ 파작파작 React 앱
```

프론트엔드에서 외부 API를 바로 호출하지 않고 Edge Function을 거치는 이유는 다음과 같다.

- 비밀 API 키를 브라우저 코드에 노출하지 않기 위해
- 요청 형식을 서버에서 통제하기 위해
- 외부 응답을 앱에 필요한 형태로 정리하기 위해
- 오류 처리와 사용량 제한을 한 곳에서 관리하기 위해

프로젝트에서는 다음과 비슷한 코드가 사용된다.

```ts
supabase.functions.invoke('search-reptile-amphibian-places', {
  body: {
    query: '병원 이름과 주소',
    latitude: 37.5,
    longitude: 127.0,
  },
})
```

Supabase 라이브러리가 내부적으로 Edge Function의 HTTPS URL에 요청을 보내 준다.

## 14. API와 REST API

API는 프로그램끼리 기능이나 데이터를 주고받을 수 있도록 만든 접점이다.

식당에 비유하면 다음과 같다.

- 손님: 클라이언트
- 주문서: API 요청
- 직원: API
- 주방: 서버와 데이터베이스
- 음식: API 응답

REST는 웹 API를 설계할 때 자원을 중심으로 URL과 HTTP 메서드를 사용하는 방식이다.

```text
GET    /pets        반려동물 목록 조회
POST   /pets        반려동물 생성
GET    /pets/1      1번 반려동물 조회
PATCH  /pets/1      1번 반려동물 수정
DELETE /pets/1      1번 반려동물 삭제
```

좋지 않은 예:

```text
/getPets
/createPet
/deletePet
```

REST에서는 URL에는 주로 자원을 나타내는 명사를 쓰고, 행동은 HTTP 메서드로 표현하는 것을 선호한다.

## 15. 인증과 권한

### 인증(Authentication)

사용자가 누구인지 확인하는 과정이다.

```text
아이디와 비밀번호 확인
→ 로그인 성공
→ 세션 또는 토큰 발급
```

### 인가(Authorization)

인증된 사용자가 해당 행동을 할 권한이 있는지 확인하는 과정이다.

```text
사용자는 로그인했음
→ 이 Q&A 글의 작성자인가?
→ 작성자라면 수정 허용
→ 아니면 403 응답
```

화면에서 수정 버튼을 숨기는 것만으로는 보안이 완성되지 않는다. 사용자가 개발자 도구로 직접 HTTP 요청을 만들 수도 있기 때문에 서버와 데이터베이스에서도 권한을 검사해야 한다.

Supabase에서는 RLS 정책이 이 역할을 담당할 수 있다.

## 16. CORS란 무엇인가?

CORS는 브라우저가 서로 다른 출처 사이의 요청을 안전하게 통제하기 위한 규칙이다.

출처는 다음 세 가지 조합으로 구분한다.

1. 프로토콜
2. 호스트
3. 포트

다음 주소들은 서로 출처가 다르다.

```text
http://localhost:5173
http://localhost:5174      포트가 다름
https://localhost:5173     프로토콜이 다름
http://192.168.0.10:5173   호스트가 다름
```

서버가 해당 출처의 요청을 허용하지 않으면 브라우저가 응답 사용을 막을 수 있다. 모바일에서 지도 API 인증이 실패했던 문제도 등록된 웹 서비스 URL과 실제 접속 주소가 다를 때 발생할 수 있다.

---

## 17. 캐시란 무엇인가?

캐시는 한 번 받은 파일이나 데이터를 임시로 저장했다가 다시 사용하는 기능이다.

장점:

- 더 빠르게 화면을 표시할 수 있다.
- 서버 요청과 데이터 사용량을 줄일 수 있다.

문제점:

- 오래된 파일이 남아 수정 내용이 바로 보이지 않을 수 있다.

PWA는 서비스 워커를 이용해 파일을 캐시할 수 있다. 개발 중 화면이 이전 모습으로 보인다면 브라우저 캐시나 서비스 워커도 확인해야 한다.

## 18. URL 인코딩

URL에는 공백이나 한글을 그대로 안전하게 넣기 어려운 경우가 있어 인코딩해서 전달한다.

```ts
encodeURIComponent('특수동물 병원')
```

결과는 `%`와 숫자가 섞인 형태가 된다.

```text
%ED%8A%B9%EC%88%98...
```

브라우저나 서버는 이를 다시 원래 문자열로 해석할 수 있다. 검색어를 URL에 직접 붙일 때는 문자열 결합보다 `URLSearchParams`를 사용하는 편이 안전하다.

## 19. 면접에서 설명하기

### 질문: URL이 무엇인가요?

> URL은 인터넷에서 자원의 위치와 접근 방법을 나타내는 주소입니다. 프로토콜, 호스트, 포트, 경로, 쿼리 문자열 등으로 구성됩니다. 제가 만든 파작파작에서는 `?tab=diary`처럼 쿼리 문자열로 현재 화면 상태를 표현했습니다.

### 질문: HTTP가 무엇인가요?

> HTTP는 클라이언트와 서버가 요청과 응답을 주고받기 위한 통신 규칙입니다. 요청에는 메서드, URL, 헤더, 본문 등이 들어가고 응답에는 상태 코드, 헤더, 본문이 들어갑니다.

### 질문: HTTP와 HTTPS의 차이는 무엇인가요?

> HTTPS는 HTTP 통신을 TLS로 암호화합니다. 전송 내용을 보호하고, 내용이 바뀌지 않았는지 확인하며, 인증서를 통해 접속한 서버를 확인할 수 있습니다.

### 질문: GET과 POST의 차이는 무엇인가요?

> GET은 주로 데이터를 조회할 때 사용하고, POST는 새로운 데이터를 생성하거나 서버에 처리를 요청할 때 사용합니다. GET의 조회 조건은 보통 URL에 들어가고, POST의 데이터는 주로 요청 본문에 들어갑니다.

### 질문: 401과 403의 차이는 무엇인가요?

> 401은 사용자 인증이 되지 않았거나 인증 정보가 잘못된 상태이고, 403은 사용자가 누구인지는 알지만 해당 작업을 수행할 권한이 없는 상태입니다.

### 질문: React에서 주소가 바뀌면 항상 서버에 요청하나요?

> 아닙니다. SPA에서는 History API나 React Router가 주소와 화면을 바꾸되 전체 HTML을 다시 요청하지 않을 수 있습니다. 다만 화면에 필요한 데이터를 가져오기 위한 API 요청은 별도로 발생할 수 있습니다.

### 질문: 왜 외부 API 키를 React 코드에 넣으면 안 되나요?

> 브라우저에 전달되는 JavaScript 코드는 사용자가 확인할 수 있기 때문에 비밀 키가 노출됩니다. 그래서 파작파작에서는 Supabase Edge Function 같은 서버 기능에 비밀 키를 보관하고 프론트엔드는 그 함수를 호출하도록 설계하는 것이 안전합니다.

## 20. 직접 해 보는 실습

### 실습 1: URL 분해하기

다음 주소를 구성 요소별로 나누어 보자.

```text
https://api.example.com:443/hospitals/12?sort=latest#reviews
```

정답:

- 프로토콜: `https`
- 호스트: `api.example.com`
- 포트: `443`
- 경로: `/hospitals/12`
- 쿼리 문자열: `sort=latest`
- 프래그먼트: `reviews`

### 실습 2: 개발자 도구 관찰하기

1. 파작파작을 Chrome에서 연다.
2. `F12`를 눌러 개발자 도구를 연다.
3. Network 탭을 선택한다.
4. 병원 검색이나 화면 새로고침을 실행한다.
5. 요청의 URL, Method, Status, Request Headers, Response를 확인한다.

로그인 토큰과 API 키는 다른 사람에게 보여 주거나 캡처해서 공유하지 않는다.

### 실습 3: 상태 코드에 맞는 상황 연결하기

- 존재하지 않는 병원 주소: `404`
- 로그인하지 않고 내 글 수정: `401`
- 다른 사용자의 글 삭제 시도: `403`
- 아이디 중복: `409`
- 서버 코드 예외: `500`

## 21. 확인 문제

1. URL에서 포트는 어떤 역할을 하는가?
2. 휴대전화에서 `localhost`는 어떤 기기를 가리키는가?
3. 쿼리 문자열과 프래그먼트의 차이는 무엇인가?
4. HTTP 요청의 네 가지 주요 구성 요소는 무엇인가?
5. 데이터를 일부 수정할 때 적절한 메서드는 무엇인가?
6. `201`은 어떤 상황에서 사용하는가?
7. `401`과 `403`은 어떻게 다른가?
8. HTTPS가 제공하는 세 가지 핵심 보호는 무엇인가?
9. SPA에서 URL 변경과 HTTP 요청이 항상 같은 일이 아닌 이유는 무엇인가?
10. 비밀 API 키를 React 코드에 직접 넣으면 안 되는 이유는 무엇인가?

### 모범 답안

1. 한 컴퓨터 안에서 통신할 프로그램을 구분한다.
2. 휴대전화 자기 자신을 가리킨다.
3. 쿼리는 요청 조건으로 서버에 전달될 수 있고, 프래그먼트는 일반적으로 브라우저 내부에서 처리된다.
4. 메서드, URL, 헤더, 본문이다.
5. `PATCH`다.
6. 새로운 자원이 성공적으로 생성되었을 때 사용한다.
7. 401은 인증되지 않은 상태이고, 403은 인증되었지만 권한이 없는 상태다.
8. 암호화, 무결성 확인, 서버 인증이다.
9. SPA는 JavaScript로 주소와 화면을 바꾸면서 전체 HTML을 다시 요청하지 않을 수 있기 때문이다.
10. 브라우저에 전달된 코드는 사용자가 확인할 수 있어 비밀 키가 노출되기 때문이다.

## 22. 마지막 핵심 정리

```text
URL = 어디로 갈 것인가
HTTP = 어떻게 요청하고 응답할 것인가
메서드 = 어떤 행동을 원하는가
상태 코드 = 요청 결과가 어떠한가
헤더 = 통신에 필요한 부가 정보
본문 = 실제로 주고받는 데이터
HTTPS = HTTP 통신을 암호화한 방식
```

면접에서는 정의만 외우기보다 파작파작에서 어떻게 사용했는지 연결해서 말하는 것이 중요하다.

> 파작파작에서는 URL의 쿼리 문자열로 현재 탭 상태를 표현하고, Supabase와 Edge Function을 통해 HTTP 요청과 응답으로 병원 및 사용자 데이터를 처리했습니다. 외부 API의 비밀 키는 프론트엔드에 노출하지 않고 서버 기능에서 관리하도록 설계했습니다.
