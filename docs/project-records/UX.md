# UX 작업 기록

## 역할

사용자 흐름, 화면 전환, 검색, 작성, 수정, 삭제, 좋아요, 임시저장, 기능 간 연결 경험을 기록한다.

## 기준

- 사용자의 최신 요구사항을 우선한다.
- 마이 펫은 단순 목록이 아니라 등록된 특수동물을 확인하고 기록 또는 루틴으로 자연스럽게 이동하는 홈 역할을 한다.
- 등록 과정은 사용자가 부담 없이 필수 정보를 먼저 입력하고, 선택 정보는 나중에 보완할 수 있게 만든다.
- 직접 입력이 필요한 경우와 목록에서 선택해야 하는 경우를 명확히 구분한다.

## 2026-07-24

### 펫 등록 흐름 단순화

- 요청 요약: 종 검색을 삭제하고, 등록 과정에서 사용자가 꼭 필요한 정보부터 작성하도록 흐름을 정리했다.
- 분석 및 판단: 종 선택 단계에서 검색창과 추천 목록이 함께 있으면 화면이 복잡해지고, 모바일에서 입력 부담이 커진다. 현재 요구사항은 목록 선택 중심이므로 검색창을 제거하고 추천 종 선택에 집중하게 했다.
- 수정 파일: `src/App.tsx`
- 핵심 변경 내용:
  - 세부 종 단계에서 `종 검색` 입력창을 삭제했다.
  - 추천 종 목록과 `목록에 없나요? 직접 입력` 흐름만 남겼다.
  - `기타` 분류는 직접 입력 흐름을 유지한다.
- 검증 결과: `npm run build` 통과.
- 남은 작업: 종 목록이 많은 분류에서 추천 노출 개수를 실제 사용성에 맞게 조정할 수 있다.

### 생일과 입양일을 나이 입력으로 통합

- 요청 요약: 입양일과 생일을 따로 받지 말고, 나이 숫자 입력으로 통합했다.
- 분석 및 판단: 특수동물은 생일이나 입양일을 정확히 모르는 경우가 많으므로 날짜를 강제하는 것보다 나이를 숫자로 입력하는 편이 사용자의 부담이 적다.
- 수정 파일: `src/App.tsx`, `src/components/my-pet/PetsScreen.tsx`
- 핵심 변경 내용:
  - 등록 확인 단계에서 생일과 입양일 입력을 제거했다.
  - `나이` 숫자 입력을 추가하고 숫자만 입력되도록 제한했다.
  - 마이 펫 카드에서는 입력된 나이를 `n살` 형식으로 표시할 수 있게 했다.
  - 기존 생일과 입양일 필드는 삭제하지 않고 호환성을 위해 타입에 남겨 두었다.
- 검증 결과: `npm run build` 통과.
- 남은 작업: 기존 데이터에 생일 또는 입양일만 있는 경우 나이를 자동 계산할지 정책 결정이 필요하다.

### 사진 추가 경험 통합

- 요청 요약: 사진 첨부를 따로 추가하지 않고, 완료 화면에 보이는 사진 영역을 사진 추가 버튼처럼 사용하게 했다.
- 분석 및 판단: 사용자가 등록 마지막 단계에서 최종 모습을 확인하면서 사진을 바로 보완할 수 있도록 하는 편이 자연스럽다. 별도 사진 추가 버튼은 제거하고 사진 카드 자체를 조작 대상으로 만들었다.
- 수정 파일: `src/App.tsx`, `src/App.css`
- 핵심 변경 내용:
  - 확인 단계의 사진 카드가 파일 선택 입력 역할을 하도록 변경했다.
  - 사진이 있으면 미리보기를 보여주고, 없으면 분류 아이콘과 `사진 추가` 안내를 보여준다.
  - 선택 정보 영역에는 성별, 나이, 몸무게를 배치해 확인 단계에서 추가 보완이 가능하게 했다.
- 검증 결과: `npm run build` 통과.
- 남은 작업: 사진 업로드가 실제 Supabase Storage 또는 현재 저장 구조와 연결되는지 별도 점검이 필요하다.

### 마이 펫 메인 화면 카드 사용성 보완

- 요청 요약: 메인 화면의 펫 추가 버튼을 줄이고, 펫 카드가 모바일과 웹에서 더 균형 있게 보이도록 조정했다.
- 분석 및 판단: 버튼이 길면 주요 정보보다 버튼이 먼저 보이고, 카드가 지나치게 넓으면 등록된 펫이 적어도 화면이 비어 보인다. 카드 밀도를 높이되 터치 가능한 크기는 유지하는 방향으로 조정했다.
- 수정 파일: `src/components/my-pet/PetsScreen.tsx`, `src/App.css`
- 핵심 변경 내용:
  - `+ 펫 추가` 버튼을 짧고 굵은 형태로 변경했다.
  - 카드 목록을 2열 기반 그리드로 조정했다.
  - 작은 모바일 화면에서는 카드가 너무 좁아지지 않도록 반응형 조건을 추가했다.
- 검증 결과: `npm run build` 통과.
- 남은 작업: 실제 모바일 기기에서 사용자가 원하는 `2개당 한 높이` 기준이 2열 고정인지, 화면별 자동 전환인지 추가 확인이 필요하다.

### 마이 펫 카드 행동 분리

- 요청 요약: 카드의 점 3개 메뉴는 수정과 삭제만 담당하고, 다이어리 이동은 하단의 루틴 버튼으로 분리했다. 세부 보기도 별도로 제공했다.
- 분석 및 판단: 카드 전체가 이동 역할을 하거나 버튼 이름이 모호하면 사용자가 수정, 삭제, 다이어리 이동을 구분하기 어렵다. `세부 보기`는 정보 확인, `루틴 만들기`는 다이어리 이동, 점 3개는 관리 메뉴로 역할을 나누었다.
- 수정 파일: `src/components/my-pet/PetsScreen.tsx`, `src/App.css`
- 핵심 변경 내용:
  - `펫 등록` 버튼으로 등록 진입 문구를 명확히 했다.
  - 카드 하단의 `루틴 만들기` 버튼을 누르면 해당 펫의 다이어리로 이동한다.
  - `세부 보기` 버튼을 추가해 현재 카드에서 보이지 않는 기본 정보를 모달로 확인할 수 있게 했다.
  - 삭제는 확인창을 거친 뒤 실행되도록 유지했다.
  - 카드 본문 클릭 이동을 제거해 메뉴 및 버튼과의 클릭 충돌을 줄였다.
- 검증 결과: `npm run build` 통과.
- 남은 작업: 루틴 생성 화면이 다이어리 내부에서 별도 생성 모드로 바로 열리도록 더 깊게 연결할 수 있다.

### 펫 등록 분류를 파충류와 양서류로 축소

- 요청 요약: 앞으로 마이 펫 등록에서는 파충류와 양서류만 사용하고, 설치류, 조류, 기타는 등록 분류와 종 목록에서 삭제했다.
- 분석 및 판단: 앱의 대상 동물 범위를 줄이기로 했으므로 새 등록 흐름에서는 선택 가능한 분류와 종 목록을 명확히 줄여야 한다. 다만 기존 데이터나 다른 화면 타입 연결이 깨지지 않도록 타입 호환은 유지했다.
- 수정 파일: `src/components/my-pet/PetCreateFlow.tsx`, `src/components/hospital-map/mapDependencies.tsx`, `src/components/my-pet/PetsScreen.tsx`
- 핵심 변경 내용:
  - 등록 분류 선택지를 `파충류`, `양서류`로 제한했다.
  - 종 선택 목록에서 조류, 설치류, 기타 종 목록을 비웠다.
  - `기타` 분류 선택 시 직접 입력하던 흐름을 등록 화면에서 제거했다.
  - 기존 펫 타입에는 조류, 설치류, 기타를 남겨 기존 데이터가 즉시 깨지지 않게 했다.
  - 기존에 지원 범위 밖인 펫을 수정할 때는 새 분류를 다시 선택하도록 처리했다.
- 검증 결과: `npm run build` 통과.
- 남은 작업: 기존에 저장된 설치류, 조류, 기타 펫을 숨길지, 마이그레이션할지 결정해야 한다.

- 핵심 변경 내용:

  - 카드 전체 클릭으로 해당 펫의 다이어리를 연다.
  - 카드에는 사진과 이름만 표시한다.
  - 점 3개 메뉴는 수정, 삭제를 위한 보조 메뉴로 유지했다.

### 파충류 종 선택 계층화

## 2026-07-25 다이어리 펫 전환 흐름 개선

### 요청 요약
